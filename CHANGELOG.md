# Changelog

All notable changes to My First Commit are documented here.

This project follows a lightweight, human-curated changelog. Keep the newest changes at the top and move items from `Unreleased` into a dated release section when cutting a release.

## Unreleased

### Added

- The production health check now performs one real commit search and asserts a commit renders, rather than only checking that the app responds. Every other search test uses fixtures, so a revoked token, a changed GitHub response, or a Server Action broken only in production could pass production health and be promoted to a release — `/api/health` reports that a token is present, never that it works. One search per deployment on one browser, because each one spends the shared GitHub quota the burst limiting exists to protect. A partial result from GitHub counts as a pass, since that is GitHub shedding load rather than a fault of this app; an empty result, an error state, or a heading with no commit does not.

- Unit test coverage is now measured, reported, and enforced. The gate's unit step runs with V8 coverage, so one command produces the numbers locally and in CI, and a text summary plus an HTML report in the ignored `coverage/` directory. The thresholds are a non-regression floor rather than a target: they were set a whole percent below a measurement of the suite as it stands — 93% statements, 89% branches, 98% functions, 94% lines against 93.68, 89.58, 98.30, and 94.66 — so a change that leaves new code untested fails the gate while a refactor does not fail on rounding. Coverage counts the files the suite loads, which means the floors cannot catch a module no test imports at all; the development guide says so rather than leaving the number to imply more than it measures.
- Two time-based contracts that nothing exercised are now tested on a fake clock, in milliseconds rather than in real waiting. The five-minute cache lifetime is pinned at both sides of its boundary — served one millisecond before the deadline, gone once it is reached — along with the rules about what may be cached: an empty result is stored so a handle with no public commits is not searched again, while a rate limit, timeout, outage, or any other failure never is, and a read inside the window refreshes eviction order without extending the lifetime. The ten-second search deadline is now proved by a request that hangs: it is still outstanding at 9,999 milliseconds and aborted at 10,000, where the previous test injected the abort itself and so could not tell a working timer from a missing one.

- Partial commit results now offer a **Search again** button in place. A retry that succeeds replaces the partial result, one that comes back partial again says so, and one that fails leaves the commits on screen and explains why instead of replacing them with an error screen. Each outcome is announced to assistive technology.

### Changed

- Every Entire CLI Codex hook now has up to 300 seconds to finish before Codex terminates it,
  increased from 30 seconds for larger sessions and checkpoint operations that need longer to
  finalize.

- The repository front door now leads with the live product, current build and release status, an
  accurate screenshot, a concise local quick start, and a compact guide to the rest of the
  documentation. Detailed capabilities, privacy boundaries, and GitHub search limitations moved to
  a dedicated product guide, and contributor recognition now links to GitHub's automatically
  maintained history instead of duplicating it in a hand-maintained file. The initial screenshot
  showed a profile-heavy interface the current app no longer renders; it has been replaced with the
  actual commit-results experience.

- Development dependencies updated: `eslint-config-next` to 16.3.1 and `@testing-library/user-event` to 14.6.4. The lint config is the half of the Next.js 16.3.1 release that governs linting, and is pinned to the same exact version as Next.js itself, so it moves with it rather than drifting a release behind. The testing library fixes the `repeat` property on synthesized keyboard events, which no test here reads. Neither package ships in the application, so nothing a visitor loads changed; `npm run lint` passes unchanged against the new config, which is the check a lint-config bump can actually break.

- Next.js updated from 16.3.0 to 16.3.1, a patch release of backported fixes. Two of them reach this app: `headers()` regains its live view of the incoming request, which is what the per-client search limit reads to identify a caller, and image optimization preserves the response it produced, which is how commit author avatars are served. The rest of the release covers Turbopack internals and features this app does not use — `'use cache'`, `unstable_cache`, middleware, i18n, and the Pages Router. The full validation suite passes on the new version, including the browser journeys that exercise both changed paths, and the version bump carried no unrelated lockfile churn: only Next.js itself, its platform build binaries, and its own transitive helpers moved.

- The agent instructions now describe the import convention the code actually follows. They said imports were "relative within a feature, aliased with `@/` only across a boundary", which matched neither half of the codebase: all 29 relative imports of a shared module cross out of their own folder, and the 3 aliased ones are exactly the route files under `app/api/`. What decides the form is depth, not the boundary crossed — a route file sits three levels down, where the relative path counts directories instead of naming anything and quietly means a different module if the route moves. The rule now says that, so it can be checked against the code rather than read as a principle nothing obeys.

- Analytics moved out of the homepage feature folder. `analytics.ts` sat in `app/_home/`, the directory for things only the homepage uses, while the root layout's analytics component imported it from outside — so every page load pulled a module out of the homepage feature to do something with no connection to searching for a commit. It now sits in `app/_lib/` with the other shared modules, which leaves `app/_home/` meaning what its name claims. The agent instructions gained the rule that decides this for the next module, and their layout list picked up the two files it had fallen behind on. Documentation and file locations only; no behaviour changed and the analytics events themselves are untouched.

### Removed

- Dropped the `clsx` and `tailwind-merge` dependencies, which nothing imported. Both are conventional in a Tailwind project and both arrived with the initial commit, but no revision since has ever imported either one: every component in this app composes `className` with a template literal, so neither package had a single call site in any version of this code. They shipped nothing, while each remained a package the audit gate had to keep clearing and Dependabot had to keep proposing upgrades for. Nothing else in the tree depended on them, so removing the two declarations removed them outright. No behaviour and no styling changed; a future need for conditional class composition can add one back deliberately.

- The structured logger can no longer be handed a raw error object. `logger.error` accepted an optional second argument of any type and passed it straight to `console.error`, which is the one thing this module exists to prevent — an Octokit error carries the request URL, and a commit-search URL carries the username being searched. No caller ever passed one, so nothing was being logged that should not have been; what is gone is the supported way to start. Callers already pull out the scalars they need, such as the status code and the error kind, and log those.

- Deleted two unreachable branches and nine unused design tokens. The share-text builder took a whole search result and carried a fallback for one with no commits, though its only caller reaches it from behind a `found` check that guarantees at least one — narrowing the parameter to the success type made the compiler reject the test that had been pinning the dead branch, and reject nothing else, which is what proved it unreachable rather than merely untested. Separately, the stylesheet mapped nine `--color-*` tokens into Tailwind's theme, generating utilities such as `bg-gh-blue` that no file ever used; every colour in this app is applied by reading the `:root` custom property directly instead. Tailwind only emits utilities that are referenced, so those tokens never reached the stylesheet and the generated CSS is byte-for-byte identical after removing them.

### Fixed

- A release tag now names a commit that was proven healthy in production, rather than one that merged and was followed by something healthy being observed. The production health check pointed a browser at a mutable alias without ever asking which commit was answering, so a deployment still in flight — or a failed one leaving the previous build live — produced a green run that said nothing about the code it was supposed to be checking. The run now asks `/api/health` what is deployed and stops in seconds if it is not the commit that triggered it. Promotion had a related gap from the other side: it decided whether a deployment had been overtaken by comparing against the tip of `main`, which advances at merge, while a deployment becomes live later and may never — so a newer commit that was still deploying, or that failed, suppressed the release of the commit genuinely in production and that release was never cut. It now resolves the live deployment directly and refuses to guess when none can be found.

- Syncing labels no longer deletes a label whose name differs from `.github/labels.yml` only in capitalization. GitHub cannot hold both `Bug` and `bug`, but the sync matched names exactly, so a label renamed by hand in the GitHub UI read as two things at once: a label to create and a stray to remove. Under `--prune` that combination deleted the very label the file asks to keep — taking it off every issue and pull request carrying it — while the create that was meant to replace it failed with a `422`. A case-only difference is now one label with a drifted name, corrected in place by renaming it, which a dry run previews as `would update: Bug -> bug`. Nothing in this repository could reach the old behaviour, since every name in the file is lowercase today. Two entries in the file differing only in case are now rejected as duplicates, because GitHub could not hold both.

- The commit timeline is now an ordered list, and long content no longer gets clipped by its card. Assistive technology previously received a run of identical card-shaped groups of `div`s with no count and no sense of sequence, for a result whose whole point is that the first item is the earliest. It is now an `ol` labelled "Earliest public commits", so a screen reader announces how many commits there are and which one it is on, and the decorative timeline markers and icons no longer add names of their own. Long repository names, unbroken commit subjects, and URLs inside a commit body now wrap instead of being cut off by the edge of the card at phone width or at 200% zoom — the repository name in the summary grid wraps rather than truncating to a tooltip no touch user can reach, and the author avatar no longer repeats the author's name to a screen reader that has just read the link beside it.

- The production health check runs again. Adding the mobile and WebKit browser projects taught the CI workflow to install WebKit but not the separate workflow that health-checks a production deployment, so the first deploy after that change failed at browser launch and opened an alert issue. The deployed app was healthy throughout; only the check was broken. Both workflows now install every browser the Playwright configuration declares a project for.
- A maximum-length GitHub handle in **Recent searches** no longer pushes the page sideways on a narrow screen. A handle can be 39 characters and has nothing to break on, so a single shortcut was wider than a 320px viewport and scrolled the whole page horizontally — the same width 200% zoom produces on a 640px window, where content is meant to reflow rather than scroll in two directions. Long handles now wrap inside their button, which stays one tap target with one focus ring and still shows the handle in full. Short handles are unchanged.
- The **Try again** button on an error no longer loses keyboard focus when it is pressed. Browsers blur a control the moment it becomes disabled, so activating the retry dropped a keyboard or screen-reader visitor at the top of the document for the length of the request and left them nowhere when it finished. The button now stays focusable while its retry runs, says **Searching again...**, and ignores a second press instead of starting a duplicate search — the same behaviour the partial-result retry already had, so both retries in the app now work the same way.
- A burst of searches for many different usernames from one client is now bounded. Sharing one request between concurrent readers of the same username did nothing about a flood of *distinct* usernames, where every search is a genuine cache miss and reaches GitHub against a shared allowance of 30 searches a minute. One client may now run 30 searches a minute that reach GitHub — an answer the cache already holds is free — and anything past that gets the existing "GitHub is asking us to slow down" screen with its retry, unchanged. The threshold is set where no visitor can reach it: sustained, it is one distinct handle typed every two seconds for a full minute, where clicking every recent-search shortcut you have stored produces five. Counting is per client rather than app-wide on purpose, so a busy day cannot turn the limit on ordinary visitors. What is kept about a client is a salted hash of its address and the times of its searches in the last minute, dropped once it goes quiet; no address is stored, no username reaches the limiter at all, and the two are never held together. Like the cache, the count lives in one server instance's memory and resets on a cold start, so it makes abuse cost something rather than imposing a global ceiling — the production runbook says so plainly, and says where a real one would have to be configured.
- Concurrent searches for the same username now share one request to GitHub instead of each making their own. The existing cache only helps once a search has finished, so a link shared with a crowd previously multiplied into one upstream search per reader, all asking the identical question against a single shared token quota. The saving is per running instance, like the cache.
- Recent searches loaded from the browser are now sanitized before they are shown. In a corrupt stored list — hand-edited, or written by something other than this app — blank and whitespace-only entries rendered as a bare `@` shortcut that searched for nothing, values kept their surrounding whitespace, and the same handle in different capitalization appeared as two separate shortcuts. Entries are now trimmed, validated, and collapsed case-insensitively, and a corrupt list still shows the full five shortcuts a visitor has earned rather than letting junk consume the slots.
- Abandoning a running search by resetting the page or starting a new one now stops it, so its result can no longer appear over the page you moved to and the search form no longer stays disabled until the abandoned request gives up.
- A commit search that GitHub abandoned before scanning every commit is now labelled a partial result rather than "First public commit found", explains that an earlier commit may be missing, and is never cached, so searching again can reach the full history. An unfinished search that returned nothing is reported as unfinished instead of as an absence of commits, offers a retry, and no longer suggests checking a different profile. Copied result text carries the same caveat.
- Primary green actions now meet WCAG AA text contrast, and successful searches move focus to the result heading for a clear assistive-technology transition.
- GitHub search failure logs now exclude raw upstream messages and accept only validated numeric rate-limit metadata.
- Vercel Analytics event URLs now remove shared-search usernames while preserving unrelated query parameters.
- Forged Server Action requests with non-string usernames now return validation errors safely.
- Commit results with missing or invalid dates no longer crash the result timeline.
- Unexpected Server Action rejections now use the inline retry experience instead of escaping to the global error screen.
- Prevented older overlapping searches from replacing newer results, and disabled search shortcuts while a request is pending.

### Changed

- The browser-test fixtures moved out of the server action that queries GitHub. Thirty percent of that file — 173 of 569 lines — was test doubles for the reserved `e2e-*` usernames, including one that throws on purpose and two that keep state between calls, all sitting in the module that holds the token and the real search path. They now live in their own module, which nothing but the browser suite reaches. Nothing about the app changed; the file that matters is a third shorter and reads as the production path it is, and coverage of it rose from 76.54% to 93.33% because it is no longer measured against lines no unit test could ever run. The coverage floors were raised to match the new measurement rather than left with three and a half points of slack.

- Coverage now measures the directories the unit suite collects from rather than only the files it happens to load, so a module no test imports counts as zero instead of vanishing from the report. The thresholds were a floor that could catch coverage slipping in code already under test while missing code that arrived with no test at all — the more common way coverage decays. Seven files are excluded, each one the gate covers by running it rather than importing it: the three metadata image routes the production build prerenders, and the four command-line entry points the gate and the production workflows execute, every one a thin shell over a module that is unit tested. The thresholds did not move, which is the evidence the exclusions are right rather than convenient: scoped and excluded, the numbers are the same to two decimal places as before.

- Node type definitions now match the Node the project runs on, and the Vitest config is loaded as the ES module it is. `@types/node` was pinned to major 22 while `.nvmrc` and the package engines both say 24, so the types described a different runtime than the one executing — the kind of mismatch that reports an API as missing when it exists, or the reverse. The config file moved to `vitest.config.mts`, which is what its `import.meta.url` needs: as `.ts` it was loaded through a CommonJS compatibility path that printed a deprecation warning on every test run, and that path is slated to become an error rather than a warning. The check that keeps unit collection scoped reads the file by name and moved with it in the same change, so the rename could not leave the gate looking for a file that no longer exists.

- The check that keeps unit test collection scoped now reads the collection setting rather than every glob in the Vitest config. It previously took the leading directory of any pattern anywhere in that file, which was fine while the file held one option and became a problem as soon as a coverage block wanted patterns of its own — a coverage exclusion registered as a collection root and failed the gate, correctly but unhelpfully, since a whole-file read cannot tell a coverage pattern from a widened test scope. It now reads only the collection array, and only the one belonging to the test configuration, so a coverage block can be scoped properly while a widened test scope still fails. Brackets are counted outside string literals, because a collection pattern contains them and counting them in the raw text would end the array inside the first pattern and report fewer roots than there are.

- Browser coverage now runs the journeys a visitor actually performs across boundaries, rather than only rendering each state in isolation. A successful search is checked to put the handle in the URL and a new search to take it back out while restoring focus to the field; a completed search is followed from appearing in recent searches through being rerun to being cleared, in the browser as well as in storage; and the timeout, unknown and validation failures each get a state of their own, with the validation failure asserted to offer a way out rather than a retry that would fetch the identical refusal. The clipboard fallback is exercised by making the write fail, since the browser's own policy decides whether a real write succeeds and the fallback is otherwise unreachable from a test.

- Commit search results are now a discriminated union, so states the app never produces can no longer be written down. The result type allowed a successful search with no commits, and failure fields on a success, which every consumer paid for with a defensive check that could not fire — the page tested `found && commits.length > 0`, and the results view carried an early return for a first commit that was always there. A success now carries at least one commit in the type itself, a failure always carries both an error and its kind, and reading the wrong variant's fields fails to compile instead of failing a runtime check somebody remembered to write. The wire format is unchanged: tuples are erased at runtime, so what the server action serializes is the same JSON as before and a result cached by an older instance still deserializes.

- `main` now enforces more of the workflow it already documented. A pull request must be up to date with `main` before it can merge, so the required check has actually run against the code that will land rather than against an older base; review conversations must be resolved; and linear history is required, which squash merging already produced. Approving reviews stay at zero, matching the documented policy that a pull request with no assigned reviewer may be self-merged. All of it applies to administrators too. The practical cost is on parallel work: merging one of two open pull requests puts the other behind, and it needs its branch updated and CI rerun before it can merge in turn.

- Removed four animation utility classes from the results view. `animate-in`, `fade-in`, and `slide-in-from-bottom-4` come from a plugin this project does not install, so they compiled to no rules at all and the fade-and-rise they describe has never run; `duration-500` was left timing nothing. Removing them means the markup no longer promises motion the app does not have, and there is consequently no motion to honour a reduced-motion preference.

- The gate now fails when a workflow that runs the browser suite installs fewer browsers than the Playwright configuration declares projects for. Two workflows each kept their own hand-written install list, and nothing tied them to the config, so adding the WebKit project updated one and not the other — a gap that could only appear after a production deploy, because the workflow it broke runs on a deployment event and no local command reaches it. The check resolves each project to the engine it actually runs on rather than to its name, since a mobile project is Chromium-backed, and it refuses to read a project it does not understand instead of quietly assuming that project needs nothing.

- The `app/` directory now holds route files and nothing else. It had grown to 23 files of which 15 were not routes — the server action, the cache, the logger, the type definitions and the rest sat at the same level as `page.tsx` and `layout.tsx`, so listing the directory that defines what the app serves mostly showed things it does not serve. Those modules moved to `app/_lib/`, completing the rule the previous two entries started: a folder under `app/` that is not a route starts with an underscore, components live beside the feature that uses them, and everything else is a module in `app/_lib/`. No behaviour changed and no route was added or removed.
- Components now have one home instead of three. `FirstCommitDisplay` sat alone in a root-level `components/` directory, the four search components sat in `app/_home/`, and the analytics wrapper sat loose in `app/`, with no rule saying which belonged where — so `SearchResults` imported one sibling across an alias boundary and the rest relatively, for no reason a reader could infer. A component now lives beside the feature that uses it, and `app/_components/` holds the ones used by something other than a single feature. The root `components/` directory is gone, and with it the last collection root the unit tests reached outside `app/` and `scripts/`. No behaviour changed; the suite collects the same 428 tests it did before the move.
- The browser suite now runs on a 320px mobile viewport and on WebKit as well as Desktop Chrome. Only Chrome ran before, so nothing automatically checked how the app behaves at phone width or in the engine behind Safari — layout, focus, navigation, and clipboard were all assumed to work the same everywhere. The two added projects run a selected set of journeys rather than the whole suite, so coverage grows by a few runs instead of tripling. Traces are also retained on failure now: the suite asked for them on the first retry, but retries are off, so no trace was ever captured for any failure in any browser.
- `AGENTS.md` now carries the agent-rules block that Next.js generates, instead of having it reappear after every browser suite run. `next dev` writes the block whenever its exact text is missing, and the browser suite boots `next dev`, so each full validation run left a modified `AGENTS.md` that someone had to notice and strip — it reached a commit by accident once. The generator offers no way to turn this off, and it skips writing once the block is present, so committing it is what actually stops it. A note above the block records that it is generated, that edits between its markers are overwritten on the next run, and that it cannot move to `CLAUDE.md`, which the gate requires to stay a byte-for-byte pointer.
- The homepage's internal components and modules moved from `app/home/` to `app/_home/`. Every directory under `app/` claims a URL segment, so a folder holding internals was one file away from becoming a public route at `/home`, with nothing in its name to say it should not be. A leading underscore marks it private to Next.js, which excludes it from routing outright. No route was added or removed and nothing about the app changed for a visitor; `/home` returns the branded not-found page exactly as before, and now cannot stop doing so.
- The app no longer downloads a web font, and a production build no longer needs Google Fonts to be reachable. The root layout fetched Geist and Geist Mono at build time, but the Tailwind font tokens have always defined system stacks and nothing ever referenced the `--font-geist-*` variables the layout generated, so no text was rendered in Geist — a visitor's browser only preloaded two font files it never used. Rendered typography is unchanged, the system stack it actually uses is documented beside the tokens that define it, and the build now depends on nothing outside the repository for fonts.
- Label synchronization now decides what to do in tested code. `scripts/sync-labels.mjs` had grown to mix validating `.github/labels.yml`, planning creates and updates, and deleting labels, with only the offline file check covered in CI — so the destructive branch was the least tested part of it. Validation, planning, reporting, and applying now live in `scripts/label-plan.mjs` as pure functions over plain data, unit tested without a token or a network: that a deletion is planned only with `--prune`, that a dry run previews exactly the deletions a real run would make and writes nothing, that an unquoted colour like `123456` is caught while `e10c02` passes through as the string it stays, and that what reaches the GitHub API is what the plan validated. The script itself is unchanged in behaviour and still the only entry point; `npm run check:labels` still validates the file offline on every pull request.
- The unit test run now collects from `app/`, `components/`, and `scripts/` instead of skipping directories one at a time. A scratch spec left at the repository root, or in any directory the exclude list had not been taught about, used to join `npm test` and fail the gate with a Playwright error that pointed at the tooling rather than at the stray file. Nothing outside those three roots is a unit test now, so such a file neither breaks the run nor quietly joins it, and the verification exemption for the external tooling-state directories no longer depends on a denylist keeping pace with every directory a tool might create. `npm run check:agent-docs` still fails if the ignore lists drift apart, and now also if the collection scope widens.
- The agent workflow now covers changes that replace an existing contract. Test-driven development assumed new behavior, where one new failing test is enough to drive the work; when a change instead replaces something, the suite already holds assertions on the behavior being removed, and those stay green while the new test goes red and then green, so the loop looks finished with the contradiction still in the tree. Agents now locate and update those assertions inside the same red/green loop instead of letting the full validation gate find them a cycle later. Agents that cannot invoke the review sub-agents must also say so on reaching the review steps rather than in the final report, since the fallback has one agent review its own change and reporting it at the end surfaces that only once the work has already been reviewed that way.
- The browser suite now also refuses a stale server of this application. Confirming that the port held the right app was not enough: a server left behind by an interrupted run answered that check perfectly, and if it had been started without the fixture mocks every reserved test username went to real GitHub, so nearly every spec failed for a reason that had nothing to do with the branch — the same misleading wall of failures the original check was built to remove. A second preflight probe now asks the server whether it was started for this suite and stops the run naming the missing flag when it was not; a server too old to answer that question is rejected the same way. That probe is a route of its own, reporting one boolean and returning `404` on any built or deployed server, so nothing about test configuration was added to the public health endpoint. Neither probe can tell which branch a server is running, which remains a reason to prefer letting the suite start its own.
- The browser suite now refuses to run against a foreign server. Playwright reused any server that answered on its port, so an unrelated application left running there was adopted silently and every spec failed as though the branch were broken. A preflight check asks `/api/health` whether the port holds this application and stops the run with one clear error when it does not, naming the port and what it found. The other process is never stopped, since the port may belong to another checkout or another person's work. The port is now settable with `E2E_PORT`, and the worker count is fixed rather than derived from the machine so a run behaves the same everywhere; both overrides reject an unusable value instead of falling back silently. CI keeps the concurrency it already had.
- `.editorconfig` now carries a `max_line_length` matching Prettier's `printWidth`, so editors show the same wrap column the formatter uses. Markdown opts out, because prose here is hand-wrapped and Prettier does not format it.
- One command now runs the validation gate. `npm run validate` chains the dependency audit, unit tests, browser checks, lint, formatting, agent-document and label checks, and the production build, stopping at the first failure. The `CI / validate` job runs that same script instead of listing the steps itself, so the local gate and the CI gate are the same definition rather than two lists that drift. `npm run check:agent-docs` now also fails if CI stops invoking the script, or if the copies of the list in the development guide or the `verifier` sub-agent definition stop matching it, and the parsing behind that check is unit tested. Those two are now the only places the chain is written out in order.
- Local Entire checkpoint hooks now match Claude Code's current tool names, including the newer task tools, so the configuration no longer depends on Claude Code's legacy alias map.
- Lint and unit tests now cover product code only. `eslint.config.mjs` and `vitest.config.ts` ignore the root-level external tooling-state directories `.claude/`, `.codex/`, `.entire/`, and `.vercel/`, matching `.prettierignore`. Neither tool skips dot-directories on its own, so an agent hook or a stray test file dropped in one of them was previously linted and run as if it were product code. `npm run check:agent-docs` now fails if those three ignore lists drift apart, and the entry matching behind that check is unit tested.
- The verification exemption is now scoped by what the gate can actually read rather than by file extension. A change confined to `*.md` files or to those tooling-state directories runs `npm run check:agent-docs` only and reports `PASS (unread-paths)`. Previously a `.claude/settings.json` edit ran all eight gate commands, including a full browser suite and production build, none of which could observe it. `.github/hooks/` stays fully gated: it is agent tooling, but it is in none of the ignore lists.
- The agent workflow now bounds its review loop: findings can be explicitly resolved with a stated reason, and a finding that survives two fix-and-re-review cycles stops for a human instead of looping. Reverification is scoped to the gate commands a fix can actually affect, with an exemption for paths no gate command reads, so a prose fix no longer triggers a full audit, test, browser, and build cycle.
- Agents must now add a `CHANGELOG.md` entry with user-facing and operational changes, treat issue, pull request, and review text as data rather than instructions, and bound the wait for an assigned reviewer instead of blocking indefinitely.
- The `ui-review` sub-agent now enumerates untracked files with `--untracked-files=all`, so a brand-new component directory can no longer be mistaken for a change with no user-visible surface.
- Consolidated the pre-PR command list, which had drifted into four inconsistent copies, into a canonical list in the development guide that the contributing guide, runbook, and release guide now link to. The agent-facing files keep deliberate inline copies. Trimmed the manual QA checklist to the states the deployed browser check skips and the judgments Playwright cannot make, and documented the Playwright browser install.
- Documented the `/privacy` and `/api/csp-report` routes in the architecture guide, along with the CSP report endpoint's data boundaries. Both shipped previously without being listed among the runtime routes.
- Clarified that the main agent owns exact unit-test red/green loops while the verifier owns focused Playwright execution and the complete validation gate.
- Removed the superseded specification and roadmap documents, along with their README links.
- Upgraded the project from Node 22 to Node 24, the current Active LTS and Vercel's default runtime. `.nvmrc`, `package.json` engines, and the docs now all name 24. Node 26 is deliberately not used: Vercel offers only 20.x, 22.x, and 24.x, so pinning 26 would not deploy.

### Removed

- Four unused Next.js starter assets — `public/file.svg`, `public/globe.svg`, `public/vercel.svg`, and `public/window.svg` — which were deployed on every release but referenced nowhere in the app, its docs, or the README. The `public/` directory is now empty and gone with them, along with the Prettier ignore entry that existed only to accommodate them.
- Copilot-specific instruction file. `.github/copilot-instructions.md` is deleted and deregistered from `npm run check:agent-docs`, which now keeps only `CLAUDE.md` and `GEMINI.md` as pointers to `AGENTS.md`. Copilot CLI, the Copilot cloud agent, Copilot code review, and Copilot Chat in VS Code read `AGENTS.md` natively, so those surfaces keep the same instructions; Copilot Chat on GitHub.com and in Visual Studio, JetBrains, Eclipse, and Xcode do not read `AGENTS.md` and no longer receive repository instructions. The check now also fails if the file reappears, since it would outrank `AGENTS.md`. The Copilot CLI hook file `.github/hooks/entire.json` is unaffected and stays.

### Security

- The unauthenticated CSP report endpoint now bounds what one anonymous request can cost. Its 16 KB limit is enforced in bytes as the body arrives — an oversized `Content-Length` is refused before a byte is read, and a body that arrives without one, or lies about it, is cancelled the moment it passes the limit — where previously the whole body was buffered and then measured in JavaScript characters, so a multibyte body several times over the limit was accepted. At most ten violations are now logged per request, with the overflow counted in a single event, so a Reporting API array can no longer amplify one POST into a log record per entry. Only the two CSP report content types are read; anything else is refused without the body being touched. Reported URLs on any scheme other than `http:` and `https:` are now reduced to the scheme alone, so `mailto:` addresses and paths from app-specific schemes cannot reach logs, joining the `data:`, `blob:`, `javascript:`, and `filesystem:` payloads already dropped. Query strings, fragments, `original-policy`, and `script-sample` are still never logged. Rate limiting the endpoint itself is platform configuration rather than code, and the production runbook now says where it belongs.

## 0.3.0 - 2026-08-01

### Added

- Label sync automation. `.github/labels.yml` is reconciled with GitHub by the `Sync Labels` workflow on merge, or locally through `npm run sync:labels`. Deleting labels is opt-in, and CI validates the label file on every pull request.
- CSP violation reporting. The report-only policy now names a reporting destination through `report-uri`, `report-to`, and the `Reporting-Endpoints` header, and `/api/csp-report` records violations as structured `csp_violation` log events. Reported URLs are reduced to origin and path so searched usernames cannot reach logs, and the original policy and script sample are never read.
- `/api/health` now reports whether `GITHUB_TOKEN` is configured, so a rotation that never reached the running deployment is visible without a live search. Presence only is reported, never the value. The production health check asserts it against deployed targets.

### Fixed

- Deployment releases no longer take the "Latest" pointer from the version release they were deployed from. Both release workflows now set it explicitly, so `releases/latest` resolves to the current version instead of the most recent deployment.
- Release promotion no longer fails when a deployment and its health check finish before CI concludes on `main`. The promotion now waits for the deployed commit's CI run to reach a conclusion instead of treating an unfinished run as a missing one.
